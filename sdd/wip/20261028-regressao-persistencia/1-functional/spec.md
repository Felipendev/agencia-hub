# Funcional
Garantir que criar/editar/excluir pessoa, cotação e lançamento financeiro não confirme persistência apenas em memória/cache. Falha de rede/HTTP, resposta nula/inválida, sessão ausente e API sem configuração preservam os registros e propagam erro para a tela. Operação remota confirmada usa retorno da API; consulta remota após remontar reconcilia o estado sem criar registros locais.
Dados em memória/cache não atravessam troca de pessoa da equipe/sessão ou agência. Requisições antigas não repovoam a sessão nova. Cache local é dispensável, com escopo da conta autenticada comprovado; cache legado sem escopo é ignorado em modo remoto. Falha do storage não desfaz sucesso da API. Modo demonstrativo só quando desenvolvimento + opt-in explícito NEXT_PUBLIC_ALLOW_LOCAL_DATA=true; produção sem API falha fechada nas escritas e consultas, sem seeds/sucesso falso. Nenhum dado de backend é apagado por descartar cache antigo.
Cobrir CRUD aplicável no provider real e cliente HTTP, reload/reconsulta, isolamento de sessão, backend 400/401/403/409/500 e rede, gravação lenta sem sucesso antecipado. Não mudar contratos de domínio/versionamento nem criar endpoints/migrations. CI deve executar suíte frontend (antes só tipos/lint/build).
